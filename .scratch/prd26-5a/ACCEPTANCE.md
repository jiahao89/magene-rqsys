## 1. 范围与判定

### 1.1 本轮要证明什么

1. 线上版本确实包含补丁（契约字段、响应头透传、错误码分层、请求体上限、`requestId` 审计）——P0。
2. 方案 §4 的 5a 完成判据：**目标环境粘贴 5 段真实聊天 → 草稿字段可用 → 人工确认创建 → 走完 分析 → 推送**（v1 已完成 5/5；v2 以 1 条冒烟复核链路未回归）。
3. 负向边界在线上可解释：限流 429 **且显示等待秒数**、未登录、空/超长（413）输入、客户端超时、PII 不落库、枚举与词典外值被丢弃、幂等重提不重复建单。
4. 新增行为的线上表现：草稿不静默覆盖、编辑后撤销「AI 填充」标记、429/503/超时文案、`intakeOrigin`／`proposerName` 落库与展示、审计 `requestId` 可串联一次请求。
5. 验收数据在验收后从应用库与 Base 彻底删除并复查（L 区，用户硬性要求）。

### 1.2 不在 5a 范围（不要当缺陷记）

- 多维表格同步（5b）：收集表、Base 分页读、`base_form` 迁移、写回、运维可见。
- 5c：需求池来源筛选、四值来源徽标、指标按来源拆分、SOP 增补、Base「来源方式」字段。
- 语义相似需求（当前只做标题子串匹配）、相似需求跳转入口。
- 姓名进模型的 PRD 例外已由用户批准并写入 `AGENTS.md`（仅聊天粘贴、只落展示字段、不参与负责人、不通知）；PRD-26 §5 的文档补记由软件产品并行完成，不阻塞功能验收，未写完记 `OBS`。
- 已知取舍：限流为进程内计数（多实例各自计数、重启归零）；日上限 100 不是跨实例硬限额。

### 1.3 判定等级

- **P0（阻断）**：版本不对、创建失败、分析→推送不通、PII 原文落库/入 Base、越权可调用、补丁声明的行为缺失。
- **P1（严重）**：错误码/文案不符、幂等失效、AI 标记不撤销、草稿覆盖、限流不生效、审计缺失。
- **P2（可记录后放行）**：相似需求未命中、延迟偏高、文案瑕疵、目标环境无法构造的边界。

每条用例记录：`PASS` / `FAIL` / `BLOCKED` / `OBS`（观察到但与预期不同的可接受现象，需注明理由）。

## 2. 数据影响与前置授权

### 2.1 会产生什么

- **验收需求**（完整回归 S1–S5 各一条；v2 补丁冒烟 1 条）进入线上需求池，并推送到生产 Base「TB需求池」。应用没有删除需求的接口，但**验收结束后必须由发布负责人直接删除应用库与 Base 的测试数据**（用户 2026-11-18 明确要求，流程见 §2.4）。
- 额外消耗：约 10–14 次 AI 抽取（含限流用例），5 次 AI 分析；均为现有额度，量级很小。
- 聊天原文**不落库**；但会先做 PII 掩码再发给模型（这是产品既定行为）。
- 首推静默（`first_push` 不写通知字段、不触发负责人通知）；验收期间**不要给这些需求分配负责人**，否则会通知到真人。

### 2.2 必须拿到的授权

- [ ] 用户/发布负责人同意在生产池创建验收需求（v2 增量只建 1 条）。
- [ ] **删除授权**：确认验收后可对生产库和 Base 执行清理（含 DELETE 应用库行、删除 Base 记录）；这是本轮额外前置条件，不得先建后补授权。
- [ ] PM（Base 使用方）知情：标题统一加 `[验收] ` 前缀；验收窗口内可能出现测试行，验收结束会删除。
- [ ] 确认执行窗口内没有其他人做 PRD-26 相关测试（限流按账号计数，会互相干扰）。
- [ ] 真实聊天原文如含客户真实手机号/邮箱/证件号，**粘贴前替换为同格式测试值**（如 `13812345678`、`test@example.com`、`110101199001011234`）；掩码是正则行为，测试值与真实值等价，且避免真实 PII 进入验收环境。

### 2.3 执行顺序（按此顺序可避免互相污染）

1. P0 执行前检查 → 2. A 抽取与创建（完整回归 5 段 / v2 冒烟 1 条，段间隔 ≥20s，避免撞 3/分）→ 3. B、C、D、G、H → 4. I 全链路轮询 → 5. F 幂等（用已创建的一条捕获请求重放）→ 6. E 限流（放最后，避免影响前面的抽取）→ 7. J 审计与日志复核 → 8. **L 清理与复查（必做）**。

### 2.4 验收后清理（L，必做；适用于此后每一次验收）

> 用户要求：验收用的测试数据必须在验收完成后删除，应用库和 Base 都要清；之后每次验收（如 §15.3 的抽取质量回归）同样适用。

| ID | 步骤 | 要求 | 实际 | 结论 |
| --- | --- | --- | --- | --- |
| L0 | 记录基线与 ID | 执行前记需求总数、今日 `intake.*` 审计数、作业失败数；每建一条记录 `requirementId`／`RQ-xxxxxx`／Base `recordId` 到 §16 | | |
| L1 | Base 清理 | 按 `RQ-xxxxxx`（或 recordId）删除本次全部 Base 行；随后按同一 RQ 号复查 **0 行** | | |
| L2 | 应用库清理 | 先导出待删行 JSON 到 `evidence/`；然后在事务内按 `requirementId` 删除来源快照、分析、推送、评分版本、幂等回执、作业、关联审计，再删需求本体；另删本轮测试产生的 `intake.*` 审计行 | | |
| L3 | 复查 | 需求总数回到 L0 基线；每个 RQ 号在需求表和 Base 均为 0；今日新增回到 0；本轮 `intake.*` 审计 0；作业失败数回到基线 | | |
| L4 | 证据归档 | 删除前后计数截图/JSON、SQL 影响行数、Base 复查截图写入 `evidence/`，并在 §16 登记 | | |

补充规则：

- 只删除**本轮**产生的数据（按 ID、账号、时间窗三重限定）；不得误删他人或历史数据；删除前必须导出 JSON 备份。
- 只做抽取、不建需求的验收（如 20 段真实聊天回归）：没有需求/Base 行要删，但本轮的 `intake.draft_extracted`／`intake.draft_failed` 审计行按同一规则删除并复查。
- 清理同时也是验收的一部分：L3 不通过，本轮验收结论不得为「通过」。
- 该流程在 v1 已实际执行并复查通过（需求总数回到 333、5 个 RQ 号在需求表与 Base 均 0 行），可作参照：[RESULTS-20261118.md](<.scratch/prd26-5a/RESULTS-20261118.md>)。

| E1 | 60 秒内连续抽取 4 次（第 4 次） | **429**，响应头 `Retry-After` 在 1–60 之间；**UI 必须显示等待秒数**（如「还需等待约 N 秒」，N 与 `Retry-After` 一致，允许 ±1s），不能只有「操作太频繁，请稍后再试」；草稿未被清空。**这是 v1 的 P1 缺陷，未显示秒数即 FAIL** | | |
| E2 | 等待 `Retry-After` 秒后再抽取 | 恢复成功；说明分钟窗口正确 | | |
| E3 | 未登录/无会话直连 `POST .../intake-draft`（隐私窗口或 DevTools 去掉凭据） | 401（或平台 SSO 重定向，记录实际），不返回草稿 | | |
| E4 | 空文本/纯空白 | 客户端按钮禁用或阻止；绕过客户端 → 400，且不消耗 AI、不新增审计 | | |
| E5 | 客户端超时（30s） | 前端在 30s 后中止请求，显示「整理超时，请重试或手工填写」类中文提示，按钮恢复可点；不产生草稿、不把超时当成功 | | |
| E6 | 超大请求体（**>2 MiB**，即 `text` 超过约 200 万字符，DevTools 构造） | 返回 **413**（`PAYLOAD_TOO_LARGE`，实现上限 `MAX_JSON_BODY_BYTES = 2 MiB`）或平台等价 413；不调用 AI、不新增 `intake.*` 审计；记录是应用层还是平台层拦截 | | |

补充记录（不作为单独用例）：

- 429 请求当前**不写审计**；`Retry-After` 在分钟限流为 1–60s，日上限可到 86400s（本次不把日限打满，见 K-6）。
- E1 的根因（v1 已定位）：妙搭客户端 `backendFetch` 经 `backend-response.toResponse()` 重建 `Response` 时只保留 `content-type`，丢弃 `Retry-After`；补丁已改为白名单透传（`retry-after`／`content-type`／`x-request-id`），必须重跑本条。
- 供应商 429 也复用 429 状态码（文案「AI 服务当前限流，请稍后重试或手工填写需求」，`Retry-After` 固定值），与每用户限流的「操作太频繁」区分；该分支目标不可构造，见 K-2。
- E5 在目标环境通常无法让服务端挂起 30s；若无法构造，记 `BLOCKED` 并以组件测试（fake timers）证据验收，见 K-12。
- E6 在妙搭入口可能先被平台 body-parser 拦截；两种来源都算通过，但必须记录返回体是否为本应用错误码。
