# [ready-for-agent] 13 — AI 输出语义、优先级边界与隐私

## 目标

让 AI 结果严格符合 Spec 02：输出可解释、可追溯的建议；不让证据完整度冒充业务价值，也不把个人身份信息发送给模型。

## 依据

- `specs/rq-sys-mvp/02-ai-analysis.md`
- `specs/rq-sys-mvp/00-foundation-and-data-contract.md`
- `specs/rq-sys-mvp/OPEN-DECISIONS.md` D-06
- `specs/rq-sys-mvp/AI-ANALYSIS-POC.md`

## 范围

- 审查并修正当前优先级计算：不得把 U/M/S/C 证据是否缺失直接计数为业务优先级分数。
- 没有经过校准并发布的规则时，所有新分析的 P0–P3 保持空值，U/M/S/C 建议继续输出。对已有分析不自动回算。
- 发布规则只有在规则数据能明确表达已批准的 U/M/S/C 评分与确定性映射时才可用于计算；若当前规则契约缺少必要的量表/校准证据，不得自行发明公式，应保持优先级为空并记录缺失的产品决策。不能把“无 P0”的事实用默认阈值掩盖。
- 保持模块词典约束、整体高/中/低置信度、总体理由和原文证据、事实/推断区分、缺失信息与版本 provenance。
- 检查模型请求的数据最小化：不发送提出人/负责人姓名、用户 ID、联系方式、附件或凭据。补足自由文本中已知脱敏标记以外的身份标识风险；无法可靠清除时，采用安全拒绝/截断策略而不是宣称已满足隐私要求。

## 验收标准

- 未发布优先级规则时，分析结果 `priority` 必为 null；不因缺少 U/M/S/C 证据而生成 P0–P3。
- 发布规则后的新分析仅使用该规则的版本化、确定性输入输出；旧分析不变。无充分规则契约/校准证据时，规则不能产生伪精确优先级。
- 返回的置信度恰为高/中/低之一，并包含总体理由和可在脱敏源文本中核验的证据。
- provider outbound payload 不包含用户 ID、姓名标记、联系方式、凭据或附件内容；提供针对自由文本姓名/用户标识的测试样例并验证安全处理。
- AI 失败、低置信度、空优先级均不阻止符合负责人规则的后续推送。
- 新增分析契约/隐私/规则测试通过，`npm run typecheck`、`npm run build` 和 `git diff --check` 通过。
