# PR-05 负责人组织维护闭环

> 批次：2026-11-06 生产就绪（PR）
> **Status**：`cancelled`（PRD-17，2026-11-06 用户明确不需要）（离职/外部人员转交子项 blocked-on-decision）
> **优先级**：P1
> **创建**：2026-11-06；基线：root `5490d75`

## 背景 / 目标

43 条 `pending_mapping`（约 13%）因无匹配在职飞书人员而长期停推，PM 在 Base 看不到这些需求；映射页「TB 负责人」列固定渲染「待匹配」，不显示真实姓名，无法判断该补谁的账号；无批量映射、无按执行人聚合、无覆盖率报表、无离职/外部人员转交流程。目标：把负责人维护从「逐条搜账号」变成可运营的闭环。

## 范围

- 待匹配队列：显示 TB 执行人姓名、需求数、最近需求；可按执行人聚合并批量映射/批量指派代理负责人。
- 批量操作：多选需求 → 指定负责人/映射；操作审计与部分失败反馈。
- 覆盖率报表：自动匹配率、待匹配数、无人认领数、按人需求数（周可见）。
- 离职/外部人员转交：标记人员状态 → 转 PM Leader/模块负责人/标记无需匹配并推送；保留审计。
- 相关：`apps/web/src/panels.tsx`（映射页/批量）、`apps/api/src/http/app.ts`（批量端点）、`domain/team-directory.ts`、`repositories.ts`、两端镜像。
