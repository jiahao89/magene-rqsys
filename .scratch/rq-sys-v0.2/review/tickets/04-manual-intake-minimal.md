# 04: 最小新建需求贯通AI与Base

**What to build:** 用户填写标题、描述、渠道后获得平台编号，并自动进入AI→空负责人Base推送；同请求重试仍为同一条需求。

**Blocked by:** 03 按平台编号复用Base旧TB行并安全切换

**Status:** draft — 待测试接缝/任务拆分确认，尚未发布为 ready-for-agent。

**Spec:** V02-S00、V02-S01、V02-S03

**Execution gate:** 无额外产品门槛；目标环境写入仍遵守项目授权门禁。

## Acceptance criteria

- [ ] V02-T04-AC01：需求池有可用新建入口，只要求标题、描述和渠道；四段提示不变成额外必填。
- [ ] V02-T04-AC02：可信登录actor、服务端时间、来源类型web_manual及RQ编号由系统生成；客户端身份/编号无效。
- [ ] V02-T04-AC03：同一次提交保留幂等键；同actor/操作/键同payload返回同一结果，同键不同payload明确冲突。
- [ ] V02-T04-AC04：需求、首快照、审计、回执与分析作业原子提交；入队失败不留下已收录却永久无任务的需求。
- [ ] V02-T04-AC05：首次AI成功/失败/超时终态后均能继续无负责人Base推送；来源配置为空不触发TB依赖错误。
- [ ] V02-T04-AC06：列表/详情正确显示已收录、AI和推送独立状态及平台编号，手工需求无TB地址、无伪同步批次。
- [ ] V02-T04-AC07：同标题另一次有效创建允许独立需求；重复同幂等请求不多占编号或多建Base行。
- [ ] V02-T04-AC08：表单有等待、错误恢复、成功详情和键盘可操作状态；新界面按需求功能局部拆出，遵循现有设计系统。
