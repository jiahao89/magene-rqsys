# 07: 手工编辑需求保留版本并安全更新Base

**What to build:** 用户修改手工需求后重跑必要分析、更新原Base行并保留PM历史；并发及旧任务不覆盖新内容。

**Blocked by:** 04 最小新建需求贯通AI与Base

**Status:** draft — 待测试接缝/任务拆分确认，尚未发布为 ready-for-agent。

**Spec:** V02-S00、V02-S01、V02-S03

**Execution gate:** 无额外产品门槛；目标环境写入仍遵守项目授权门禁。

## Acceptance criteria

- [ ] V02-T07-AC01：手工事实可编辑，TB事实仍只读；使用期望来源版本和请求幂等键。
- [ ] V02-T07-AC02：并发冲突明确返回并保留未提交内容；规范化后无变化不新建快照或分析。
- [ ] V02-T07-AC03：影响需求含义的变更原子保存新版本/审计/主分析任务；渠道/链接等元数据变化只更新投影，不重置PM状态。
- [ ] V02-T07-AC04：旧AI、旧push、旧租约不能结算为当前结果或写回旧内容；当前状态与输入版本一致。
- [ ] V02-T07-AC05：实质变更前读取并保存Base PM快照，成功后写同recordId并置待处理；快照失败该行不改、可重试。
- [ ] V02-T07-AC06：人工负责人、人群确认和Base PM确认不被来源编辑或AI重跑覆盖。
- [ ] V02-T07-AC07：内容通知按新实质版本发给当前负责人，无负责人回落PM Leader；重放同请求/任务静默。
- [ ] V02-T07-AC08：保存后详情刷新能区分旧分析与新分析，不将旧建议当作当前已分析。

## Verification

内容编辑→新快照/worker→同Base行的集成行为；覆盖并发更新、旧任务迟到、事务失败和PM快照失败。

新增/更改行为须在本切片完成本地验证，并同步两仓契约与必要实现；目标环境未执行时标记“已实现，未在目标环境验证”。不将全部测试或双仓同步拖到最终验收票。
