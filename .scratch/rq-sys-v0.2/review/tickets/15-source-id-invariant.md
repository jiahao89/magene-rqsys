# 15: 对齐同标题不同TB ID的保留规则

**What to build:** TB不同ID的同标题需求各自保留，同一ID的分页重放只处理一次，手工同标题需求也互不合并。

**Blocked by:** None（无代码前置；仍需检查下列外部门槛）

**Status:** draft — 待测试接缝/任务拆分确认，尚未发布为 ready-for-agent。

**Spec:** V02-S00

**Execution gate:** G-ID：现有代码与AGENTS冲突。本草案推荐来源ID优先；确认后实施，若业务坚持标题过滤则需先修改数据完整性定义。

## Acceptance criteria

- [ ] V02-T15-AC01：按AGENTS的来源ID不变量核对现有标题过滤；取得本草案确认后，取消以同标题丢弃不同TB ID的行为。
- [ ] V02-T15-AC02：保留跨分页重复同一ID去重、分页停滞保护、source_only和指定ID重试能力。
- [ ] V02-T15-AC03：不同ID同标题、规范化后同标题、空标题、内容后续变化均可独立导入和追溯。
- [ ] V02-T15-AC04：导入计数说明接口取得数、重复ID数、实际处理数；不把标题相同当数据已经对齐。
- [ ] V02-T15-AC05：已有数据不批量删行、不按标题合并，也不推断过去缺失记录就是测试数据；后续授权同步按源ID恢复。
- [ ] V02-T15-AC06：根仓与妙搭等价；与手工创建幂等和Base平台键用例共同回归。
