# 综合分按版本显示（PRD §4.2.7.1 / PRD-36）

- 日期：2026-11-28
- 提交：根仓 `49ee272`（已推 `e1cd5d9..49ee272`）、妙搭 `074d13d`（已推 `8366dc3..074d13d`）
- 规则：v4（0–100 制）显示整数 + ` / 100`；v2/v3 旧 U/M/S/C 制保留两位小数。只改显示，不改存储、公式、阈值、P 判定。

## 改动

新增两个格式化函数（`requirements-page.tsx`，两仓逐字一致）：

- `compositeScoreNumber(score, inputs)`：v4 取整，v2/v3 保留两位小数；
- `formatCompositeScore(score, inputs)`：v4 追加 ` / 100`，v2/v3 只给数字。

四个展示点统一走它：

| 位置 | v4 | v2/v3 |
|---|---|---|
| 摘要卡主视觉 | `80` + 小号 ` / 100` | `6.40` / `15.20` |
| AI 建议标签（初筛卡右上） | `80 / 100` | `6.40 分` / `15.20 分` |
| 评分区主视觉（Statistic） | 取整 + ` / 100` 后缀 | 两位小数 |
| 评分历史「分数/P」 | `80 / 100 · P1` | `6.40 · P3` |

历史行按**该行自己的版本**取格式，不把旧版分数套成 0–100。

## 实测（1440，真实 DOM 取值）

| 需求（mock） | 摘要卡 | AI 建议标签 | 评分区 | 历史行 |
|---|---|---|---|---|
| v4 / 80 | `80 / 100` | `80 / 100` | —（v4 走初筛卡） | `80 / 100 · P1` |
| v3 / 6.4 | `6.40` | `6.40 分` | `6.40` | `6.40 · P3` |
| v3 / 15.2 | `15.20` | `15.20 分` | `15.20` | `15.20 · P2` |

页面全文不再出现 `80.00` 或 `6.40.0` 这类重复小数。截图：`format-v4-80-summary.png`、`format-v3-6.40-summary.png`、`format-v3-15.20-summary.png`、`format-v3-6.40-history.png`。

## 用例

- 新增「formats an old U/M/S/C score with two decimals…」：主视觉 `15.20`、历史行 `6.40 · P3` 与 `15.20 · P2`，且不出现 `/ 100`。
- v4 用例（既有 fixture 改 80 分）：断言出现 `80 / 100`、不出现 `80.00`；先把标签改回旧格式确认该断言**会失败**，再在修复后确认通过。

## 备注

- 摘要卡的 `/ 100` 原本与数字是两个元素，`textContent` 会读成 `80/ 100`；已在单位文案前补一个空格，现在读出来是 `80 / 100`。
