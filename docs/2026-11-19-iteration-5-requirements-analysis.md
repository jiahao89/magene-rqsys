## 3. 依赖与前置

### 3.1 5b：Gate 0 必须先过

1. **收集表本体**：由 PM 运营/用户在目标 Base 新建一张「需求收集表」，**必须与 PM 的「TB需求池」分开**，否则系统会把自己写回的行再读成新需求，形成循环。字段与 `RequirementIntakeSchema` 对齐：标题、描述、来源渠道、需求类型、产品型号、约束说明、补充链接、功能模块、提出人（提出人按人员字段收集，系统侧只落展示文本，不参与负责人匹配）；系统写回：系统需求 ID、同步状态、同步说明。
2. **应用凭据权限**：现有应用凭据必须能**分页读取**这张新表、能**写回**结果；本地无法核实，必须在目标环境用真实凭据验证。验证不通过，5b 直接 BLOCKED。
3. **代码与迁移**：新增来源类型 `base_form` + 外部 ID 列（Base `record_id` 作来源身份），需要一个新迁移（当前空号 0029）+ 妙搭 Drizzle schema 同步；调度走现有 automation tick；写回失败要在运维页可见。
4. **口径定稿**：收集表字段/选项与 `REQUIREMENT_INTAKE_CHANNELS`/`REQUIREMENT_INTAKE_TYPES`/已发布模块词典对齐；谁负责建表、谁负责字段映射签字，需在开工前明确。
5. **验收与通知**：5b 验收会创建需求并推送 Base，可能触发 PM 侧正常通知；验收前必须确认通知静默或使用安全测试配置，避免打扰 PM。
6. **验收数据清理**：验收后按 5a 的清理流程删除应用库与 Base 两侧数据，并复查总数。

### 3.2 5c：Web 先行，Base 字段单独排

- **5c-1（Web）**：不需要外部依赖。来源判定用 `sourceType` + `source_payload.intakeOrigin`；列表加来源筛选与徽标；5a.1 之后创建的聊天粘贴需求应显示「聊天粘贴」，5a.1 之前的只能按「手工」处理（已登记为无法回溯）。
- **5c-2（Base）**：需要 Base 管理员在「TB需求池」新增「来源方式」字段（建议单选，选项：Teambition / Web 手工 / 多维表格 / 聊天粘贴），并在 `BASE_FIELDS_JSON` 配置。**历史行是否回填**要先定：
  - 建议：对 `source_type`/`intakeOrigin` 可判定的行做一次性回填（只写新字段、不碰 PM 字段、不通知），先 dry-run 对账再执行；回填前确认 Base 通知工作流不会因「来源方式」字段变化触发（必要时调整工作流条件或窗口内停用通知）；5a.1 之前的聊天粘贴行无法判定，保持空白并记录。
  - 保守方案：只在新推送时写入，历史行留空；需明确告知 PM「Base 来源方式只覆盖新推送」，否则会被当成数据缺失。

### 3.3 AI 质量 20 段回归

- 需要 20 段真实聊天文本（用户/PM 提供，先脱敏；不要用生产客户原文直接外发）；每段标注期望标题、渠道、类型、模块、提出人、约束。
- 不需要新代码能力，复用 `intake-draft`；只调抽取接口、**不创建需求**，验收后清理产生的 `intake.*` 审计行。
- 采纳率/修改率需要试点真实使用数据，试点未启动前不做。

### 3.4 token/成本统计（另立项）

- 供应商 `usage` 当前未落库；要做需要新增持久化字段/表与迁移，并按调用类型（分析/聊天抽取）归集。若还要折算金额，需要价格表与变更机制。
- 建议一期只统计 token 数，不做金额；但既然用户已说「另立项」，本迭代不排。

### 3.5 P3 兜底文案

- 位置 `apps/web/src/App.tsx:60`；当前「无法连接到本地 API。请启动 API 服务后重试。」改为「服务暂不可用，请稍后重试。」；开发细节留在日志/开发模式。无依赖。

### 3.6 AI 状态区 BLOCKED 收口

- 需要线上库执行工具（至少 SELECT/EXPLAIN；B/D7 还需要 `system_flags`/`audit_events` 的有限 INSERT/DELETE）或由后端代跑 SQL；禁止 DDL。窗口约 2 分钟（暂停 flag），要避开同步和待分析作业。
- 若拿不到工具：维持「有条件通过」，把 6 项 BLOCKED 的残余风险写进发布记录，不冒充通过。

## 5. 建议优先级与排期

**优先级**

- **P3/暂缓**：AI 采纳率闭环、token/成本统计、优先级严格排名、试点准备。

**10 个工作日排期（建议）**

| 时间 | 5b | 5c / 质量 / 文案 | 备注 |
|---|---|---|---|
| D0–D2 | Gate 0：建收集表、验证分页读/写回权限、字段映射签字 | 5c-1 方案；20 段样本开始收集 | Gate 0 不过则 5b 顺延 |

| 严格排名改分布 | PM 信任与 Base 同步风险 | 维持暂缓；启动需维护窗口、回滚与 PM 沟通 |

| 10 天排期偏紧 | 5b 验收被压缩 | 5b 是条件项；Gate 0 失败即切 Fallback，不硬塞 |
