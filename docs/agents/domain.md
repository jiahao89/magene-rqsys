# Domain Documentation Rules

- This repository is the canonical implementation source for RQ-Sys. MVP specs, decisions, contracts, and architecture notes live under `specs/rq-sys-mvp/`.
- Approved V0.2 and post-MVP increments live under `specs/rq-sys-v0.2/`, `docs/2026-10-21-rq-sys-v0.2-prd.md`, and `docs/2026-11-06-production-readiness-decisions.md` (PRD-13–PRD-33); read the relevant numbered spec, field-ownership guidance, and decision gates when changing manual intake, unified identity, audience analysis, scoring v2, Base key compatibility, multi-pool isolation, assessments, PRD prompts, recycle bin, or RICE/Kano Beta.
- Before changing behavior, read the root `AGENTS.md`, `CONTEXT.md`, `specs/rq-sys-mvp/README.md`, the relevant numbered spec, `OPEN-DECISIONS.md`, and `openapi.yaml` when touching APIs.
- Feishu MVP PRD revision 60 controls MVP baseline behavior, while `docs/2026-10-21-rq-sys-v0.2-prd.md` and `PRD-13–PRD-33` control approved V0.2 and later increments. `AGENTS.md` states the domain invariants; do not infer new product behavior from implementation convenience.
- Ticket status indexes live under `.scratch/rq-sys-mvp/issues/README.md`, `.scratch/rq-sys-v0.2/issues/README.md`, and `.scratch/rq-sys-production/issues/README.md`. Individual historical ticket drafts were archived/removed from the working tree in commit `98d674c` (recoverable via `git show 98d674c:.scratch/...`; see `.scratch/README.md`).
- Treat local tests and adapters as local implementation evidence only. “Integrated”/“connected” claims require actual target-environment verification; otherwise say “implemented, not verified in target environment.”
- Miaoda `@NeedLogin()` + trusted `req.userContext.userId` identity adaptation is implemented in `rq-sys-miaoda/` and must be verified after releases. Do not deploy/write to Miaoda, mutate target databases, or modify external collaborators without explicit user confirmation and the safety gates in `AGENTS.md`.
