# V0.2精简字段归属与覆盖规则（2026-10-23 已确认拆分）

| 字段/对象 | 必填 | 权威方 | 来源/编辑规则 | Base / AI |
|---|---|---|---|---|
| 内部UUID | 系统 | RQ-Sys | 不可改，跨表关联 | 不作为给模型的业务文本 |
| RQ平台编号 | 系统 | RQ-Sys | 跨来源唯一、生成后不变；回放复用 | Base通用键，首列 |
| 来源类型 | 系统 | RQ-Sys | TB或手工，不可手改 | 通用来源投影，模型不需要身份标识 |
| TB项目/需求ID | TB才必有 | TB | 按既有项目配置+源ID去重；手工为空 | TB需求ID用于追溯，不再通用Base键；模型不接收 |
| TB地址 | 否 | TB/已验证地址规则 | 仅TB适用，不为手工拼接 | Base位于TB ID后；不把敏感URL参数送模型 |
| 标题/描述 | 手工必填 | TB或RQ-Sys按来源分支 | TB只读；手工编辑生成实质来源版本 | 定义投影，去个人信息后用于主AI |
| 来源渠道 | 手工必填 | 手工录入/TB批准映射 | 固定业务类别；不等于连接器类型 | 可投影；模型只用必要语义 |
| 产品/型号 | 否 | 来源分支 | 仅明确提供值，可影响实质版本 | 批准业务上下文 |
| 人工需求类型 | 否 | 手工录入 | 8类受控值，与AI建议分开 | AI不可覆盖，Base按批准字段投影 |
| AI需求类型建议 | 否 | 分析版本 | 原文有依据，不覆盖人工输入 | 与人工字段独立 |
| 边界/限制 | 否 | 来源分支 | 未知不补造；变化影响分析依据 | 批准上下文，实质更新保护PM快照 |
| 补充说明/来源链接 | 否 | 录入人 | 内容影响含义则实质变化；只改追溯链接是元数据 | 不自动打开链接或读取附件；模型不接收PII链接 |
| 录入人/创建时间 | 系统 | 可信上下文/服务端 | 不允许客户端冒充，审计留痕 | 不送模型，不要求联系信息 |
| 录入模块 | 否 | Web录入/PM | 受控词典，保留人工值；建议不等于最终确认 | 不覆盖Base PM确认模块 |
| AI模块建议 | 否 | 分析版本 | 受控词典或无法识别 | 现有AI模块列；超目标选项按既有省略策略留证 |
| 通用负责人/ID类型 | 否 | 显式分配/来源映射 | 按需求保存，历史/分配版本；不全局改其他需求 | 人员字段，通知选人；绝不送模型 |
| Base人工负责人 | 否 | Base | 非新分配命令不得被旧本地值擦除；仅推送时读以保护和选收件人 | 不成为Web业务状态回读 |
| AI人群建议 | 否 | 分析版本 | L1–L6多选，每项理由/证据 | AI上下文；Base非必需新增列 |
| PM当前人群/确认标记 | 否 | RQ-Sys | 可明确空集，有独立修改版本和历史 | 不冒充AI值；不自动推通知或重置PM状态 |
| U/M/S/C九项输入、α与依据 | 否 | AI建议版本/人工确认版本 | AI直接给分，必须带依据或显式假设；PM可改单项/α，版本化审计 | 主AI结果；评分明细不新增Base字段 |
| 综合分/P0–P3 | 条件计算 | 已发布评分v2规则 | 服务端按固定公式计算；人工只改输入/α；旧结果不回算 | 当前P按既有Base推送投影 |
| PM状态/确认模块/确认优先级/备注等 | 否 | Base | 实质变化先快照，再置待处理；不得覆盖确认内容 | Web不增加回读/业务编辑 |
| RICE输入/配置/结果 | 否 | 人工输入+版本化配置 | 独立Beta；缺项/未配置为草稿，不代算主优先级 | 本期不投影Base，不自动送模型 |
| Kano资料/报告/复核 | 否 | 批准快照+AI假设/人工复核 | 每次运行固定输入版本；复核不变成真实问卷 | 仅手动运行；不进入主优先级/推送 |

来源渠道先采用PRD已列六类：销售、售后、电商、运营/用研、终端用户、产品/研发/测试。若正式PRD后来批准更精细枚举，依其更新；不根据TB字段名称自创映射。

手工需求类型采用PRD八类：新增功能、功能扩展、体验优化、性能优化、质量修复、安全合规、成本效率、技术治理。

Source snapshot保持追加式；负责人/人群/评分等人工操作有独立历史，不通过修改TB字段伪造来源事实。后续若将Base PM业务字段迁入Web，需另立归属与冲突方案。
